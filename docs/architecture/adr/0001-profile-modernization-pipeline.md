# ADR 0001: GitHub Profile Repository Architecture

## Status

Accepted

## Context

This repository is the special GitHub profile repository for `tejaswin-amara`. Its primary output is the rendered profile README, not a hosted web application.

The previous version contained a small Node/Render telemetry service and an application-oriented architecture plan. That added runtime and deployment dependencies without improving the GitHub profile itself.

## Decision

Keep the repository intentionally static and GitHub-native:

- **Profile UI:** Markdown rendered by GitHub.
- **Visual system:** Versioned SVG assets under `assets/`.
- **Project links:** Direct links to maintained GitHub repositories.
- **Activity visualization:** GitHub contribution snake generated by GitHub Actions and published to the `output` branch.
- **CI:** Link validation and secret scanning.
- **Deployment:** None. The profile is rendered directly by GitHub.
- **External runtime telemetry:** Removed. The profile must not depend on a separate server merely to render its README.

## Consequences

### Positive

- No application server or hosting dependency.
- No fabricated or hard-coded runtime metrics.
- Fewer secrets, dependencies, and failure points.
- The profile remains portable and easy to maintain.
- CI focuses on the things that can actually break the profile: links and repository content.

### Trade-off

Dynamic analytics and runtime-generated profile cards are intentionally not part of the base architecture. If they are added later, they should be introduced as an isolated service with a documented data source, privacy model, failure behavior, and maintenance owner.
